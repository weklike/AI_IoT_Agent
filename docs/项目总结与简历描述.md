# 充电设备监控与智能运维 Agent：v2.0项目总结

## 定位与实现

单机、纯软件充电设备演示系统，面向后端、物联网平台、AI应用和全栈岗位。三台独立MQTT设备与FastAPI/SQLite/Vue三页面组成“充电运行→异常发现→知识与巡检分析→工单处理→恢复验证→事件复盘”闭环。

已实现受限启停、整数电量积分与报告确认、equal/priority功率计划、告警规则及恢复、工单生命周期、24篇版本化FTS5检索、九工具Agent与只读巡检。设备控制通过页面API执行；Agent没有启停、改功率或迁移工单状态的工具。

完整M4与最终真实模型语义验收尚未完成，不能写“全部验收通过”。fixture只替换模型响应，真实工具/数据库/事务仍执行；模型效果必须与工程链路分开表述。

## 可用的简历描述草案

**充电设备监控与智能运维 Agent｜个人项目**

Python 3.12、FastAPI、Pydantic 2、SQLAlchemy 2、SQLite/WAL、MQTT、Vue 3、TypeScript、ECharts、Docker Compose、pytest、Playwright。

- 构建三台独立MQTT软件设备的充电运维闭环，实现双唯一键去重、乱序快照与新鲜度判定；会话报告提交后确认，使用整数余数积分和原子检查点避免重复计量与重启回退。
- 实现受限功率分配与先降后升执行，按未确认命令保守核算上界；控制回执与遥测效果分别判定，部分失败不自动重试或伪报预算生效。
- 实现单Agent九工具、请求幂等、服务器授权/证据检查和整轮执行预算；结合版本化FTS5检索与同run引用校验，保留模型消息、工具轨迹和真实数据库结果。
- 实现告警确认/恢复与工单验证关闭，使用部分唯一索引和短事务维护未关闭工单幂等；通过隔离Compose、实际Broker、服务层并发和浏览器测试验证闭环。

## 表述边界

20并发是工单服务层独立会话测试，不是20个同时运行的Agent。软件模拟、电量演示规则与本地压力结果不代表真实充电安全认证或生产部署规模。没有真实人工评审时不填写真实模型准确率；引用格式通过不代表数值、时间和建议语义都正确。
