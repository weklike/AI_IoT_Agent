# 充电设备监控与智能运维 Agent：项目总结与简历描述

## 1. 项目定位

本项目是一个面向充电设备的物联网监控与 AI 辅助运维系统，适合用于投递 Python 后端、物联网平台、AI 应用和全栈开发岗位。

项目采用三台软件模拟设备，在单机环境中完成“设备遥测采集 → 状态监控 → 自然语言分析 → 授权创建检修工单”的业务流程。

## 2. 已实现功能

- **设备监控**：模拟三台充电设备，采集温度、电压、电流和功率，展示在线状态、过温告警与历史曲线。
- **场景模拟**：支持正常、过温、暂停上报，通过 MQTT 命令及回执确认场景切换；暂停上报时保留控制订阅。
- **AI 运维**：用自然语言查询设备、分析历史、获取故障排查说明，并在用户授权后创建检修工单。
- **网页交互**：提供设备总览、设备详情和 Agent 对话三个页面，支持工具轨迹、Markdown 回答和刷新恢复任务。

## 4. 技术难点与解决方式

### 4.1 消息可靠性与设备状态一致性

MQTT 消息可能重复、乱序或回放，需要区分历史入库与当前状态更新，避免旧数据让设备“重新上线”。

- 使用 `message_id` 和 `(device_id, boot_id, seq)` 双重唯一约束，区分重复消息与内容冲突。
- 合法旧样本可以进入历史，当前快照只采用时间戳严格更新的样本。
- 将设备连接状态与数据新鲜度分别判断，明确区分 online、offline、unknown 和 stale。

### 4.2 Agent 执行控制

模型可能调用错误工具或长时间不返回，需要限制执行能力与耗时，并保留可追溯结果。

- 提供状态查询、历史查询、故障说明和工单创建四个进程内业务工具。
- 执行前进行工具白名单、参数及权限校验；授权信息由服务器注入。
- 设置最多 6 次模型请求、8 次工具调用，以及单次模型 20 秒、工具 3 秒、整轮 90 秒的执行预算。
- 保存模型消息、工具调用和实际结果，正确配对模型侧调用 ID 与服务器内部调用 ID。

### 4.3 工单幂等与事务一致性

重复点击、并发建单和写入超时可能产生重复操作或不确定结果。

- 使用 `request_id` 实现任务幂等，同一请求复用原任务。
- 建单依据必须来自本任务、本设备的成功只读工具记录。
- 使用数据库部分唯一索引，限制同设备同原因最多一张 OPEN 工单。
- 工单变更与当前工具结果在同一事务中提交；提交边界超时后按本次调用记录确认结果，避免把旧工单误认为本次成功。

### 4.4 查询性能与可验证测试

历史查询中的 ORM 实例化和 JSON 序列化会产生额外开销，优化时仍需保留完整统计口径。

- 通过性能分析定位逐条 ORM 实例化及递归 JSON 编码开销，优化查询字段读取和序列化流程。
- 保持完整窗口统计，不通过删减样本或缩小窗口满足性能目标。
- 使用临时 SQLite、独立 Compose 项目、随机端口和 MQTT 前缀隔离测试资源，保存成功与失败证据。

## 5. 简历描述：可直接使用

**项目名称：充电设备监控与智能运维 Agent｜个人项目**

**技术栈：** Python、FastAPI、MQTT、SQLite、SQLAlchemy、Vue 3、TypeScript、ECharts、Docker Compose、pytest、Playwright。

**项目描述：** 面向充电设备运维场景，基于 FastAPI、MQTT、SQLite 和 Vue 3 构建单机演示系统，实现三台软件模拟设备的遥测采集、异常监控、自然语言分析与授权检修工单创建。

- **设备数据链路：** 实现三个独立 MQTT 客户端及正常、过温、离线模拟场景，通过消息 ID 与设备启动序号双重唯一约束处理重复和冲突消息，结合时间戳更新规则与数据新鲜度判定，保证历史数据和当前状态的一致性。
- **Agent 工具执行：** 接入真实模型工具调用协议，实现状态查询、历史分析、故障说明及工单创建四个业务工具，加入参数校验、授权控制、调用次数限制、超时预算和完整执行轨迹。
- **工单一致性：** 基于 request_id 实现任务幂等，通过本任务证据校验、数据库部分唯一索引及事务提交，约束同设备同原因仅保留一张 OPEN 工单，并完成 20 并发事务验证。
- **性能与工程验证：** 优化查询字段读取和序列化流程，在本地 **10 并发、1000 次请求**测试中，查询 API P95 达 **404 ms**；三台模拟设备连续运行 **60 分钟**，确认发布的 **5391 条消息全部入库**，遥测入库 P95 为 **79.5 ms**；完成 Docker Compose 部署及 **19 项页面测试**。
