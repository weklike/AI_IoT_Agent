# v2.0 的3—5分钟演示脚本

这是操作稿，不表示已经完成真人录屏或模型语义验收。使用本次新建的演示实例；已有库先按README完成离线备份/升级。确认页面的fixture/real标签，未完成真实评审时使用“fixture工程闭环演示”的说法。

## 准备

```bash
[ -e .env ] || cp .env.example .env
uv sync --locked
npm --prefix frontend ci
SIMULATOR_MODE=operations docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

打开http://127.0.0.1:8080。三台均应有新鲜v2遥测，初始IDLE、0W。预先打开一份实际完成的巡检报告或准备点击“一键巡检”；工单创建需要本次勾选授权并明确说“创建”。首次下载镜像不计入预构建冷启动时间。

## 0:00—0:50：开始会话并分配功率

简述三台是独立MQTT软件客户端。依次进入三台详情，请求20,000W并开始充电，等命令效果已验证。说明初始限制0W是预期，不是故障。

回总览，预览45,000W/equal，展示三台15,000W目标，再执行并等待VERIFIED。指向已确认预算和实际样本功率；说明仅预览不会下发，PARTIAL不能称全部生效。时间不足时可提前完成三台会话，但现场展示预览/执行。

## 0:50—1:40：过温、确认与巡检

进入CHG-002，点击“模拟过温”，先看匹配场景ACK，再看新鲜高温样本和ACTIVE告警。点击“确认已知晓”，指出它仍然ACTIVE。

回总览运行10分钟只读巡检，打开报告，区分服务器保存的逐设备事实与模型分析文字。展示真实工具轨迹和DATA引用；fixture不是模型准确率，巡检不能偷偷停设备或建单。

## 1:40—2:35：知识依据与授权建单

在Agent页输入“知识检索：2号桩过温排查资料”，展开实际来源卡片，指出source/version/chunk及authored_simulation归属。资料只解释本软件系统，不能证明真实硬件损坏。

开始新任务，勾选本次建单授权，明确输入“分析2号桩最近10分钟的过温并创建检修工单”。展开实际order_id及工具返回的created字段。刷新恢复相同run；不要把新建操作当成默认查询行为。

## 2:35—3:45：处理、恢复与关闭

回CHG-002详情，工单开始处理，填写“已核对模拟场景，等待新鲜恢复证据”，标记RESOLVED。尝试关闭，展示仍过温/告警未恢复时的明确拒绝。

点击“恢复正常”，观察低于55°C连续10秒的新鲜样本，等告警CLEARED后再关闭。展开处理记录，核对恢复样本和时间。RESOLVED不是CLOSED，填写说明不是恢复证明。

## 3:45—4:30：事件复盘与边界

打开事件时间线，关联场景命令、告警、工具和工单迁移；点击事件定位历史曲线，解释只读复盘不会重放命令。若时间允许，展示固定脚本入口及取消语义；完整60秒脚本另有测试证据，不必挤进本次短演示。

用实际验收报告展示查询、反馈和稳定性数字，并指明对应版本及范围。最后恢复正常场景、停止本次演示会话，保留工单与历史证据。不要清空数据库。

## 结束说明

一个Agent、单worker、SQLite、四Compose服务，适合单机演示。没有实体硬件联锁、鉴权/多租户、支付、模型训练、MCP或向量RAG。真实模型效果需最终60+72案例及真人逐例复核；未满足前不宣称完整作品通过M4。
