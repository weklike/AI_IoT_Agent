# 3—5 分钟演示脚本

这是可执行的演示安排，不表示已经完成真人录屏。先确认当前证据状态，真实模式未验收时必须使用“fixture 工程演示”表述。

## 准备

```bash
[ -e .env ] || cp .env.example .env
uv sync --locked
npm --prefix frontend ci
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

打开 http://127.0.0.1:8080。确认模型模式标签、三台设备在线、数据新鲜。第一次下载镜像可能较慢，不把下载耗时计入已预构建后的冷启动。

## 0:00—0:40 / 范围与正常状态

说明三台设备是独立 MQTT 客户端，采用纯软件合成数据；网页数据由后端返回。展示设备 ID、温度单位、样本时间。解释 online 与 data_fresh 是两个不同维度。

## 0:40—1:20 / 注入过温

进入 CHG-002，点击“模拟过温”。先展示“等待设备回执”，再看到“已应用”和过温样本。切换 10/30/60 分钟历史，说明没有补造启动前数据。60 °C 是演示阈值，不是硬件认证标准。

## 1:20—2:20 / 查询依据

进入 Agent 页，输入“分析2号桩最近10分钟的温度，给出排查建议”，保持工单授权关闭。查看状态/历史/故障说明工具结果、内部调用 ID、真实指标与说明版本。明确 fixture 是确定性替身；只有真实模型评测通过后才能描述实际模型效果。

## 2:20—3:20 / 授权与幂等

开始新任务，勾选本次授权，输入“检查2号桩过温并创建检修工单”。展开 create_work_order 查看真实 order_id、created 和证据。刷新页面，展示同一 run_id 和服务器轨迹。再次以新任务提交同样问题，工单应复用同一 OPEN 编号、created=false。

## 3:20—4:30 / 离线与恢复

在 CHG-003 详情点击“暂停上报”。说明按钮操作不是立即离线：先数据过期，最后新鲜接收超过 15 秒才 offline。恢复 normal，等待新鲜样本恢复 online。最后恢复 CHG-002 normal。

## 结束时说明限制

没有真实硬件、设备电路控制、模型训练、MCP、向量 RAG 或多 Agent。性能及模型数字只引用对应证据目录的实际报告。不要将脚本、fixture 或计划阈值说成实测真实模型成功率。
